# 项目状态

> 最后更新：2026-10-25

## 当前阶段

初版 MVP 已完成，具备“食材输入或图片识别 -> 菜品研发 -> 结构化输出 -> 上架文案 -> 参考图或生成图”的主要链路。

当前的重点不是继续增加框架，而是补齐经营数据、历史管理和可验证性。

## 已实现

### 食材理解

- 支持上传一张食材或冰箱照片。
- 使用多模态模型识别食材。
- 用户只询问“有哪些食材”时，流程停留在识材结果，不自动生成菜谱。
- 多轮对话会保留上一轮识别出的食材，后续可继续要求研发。

### 菜单研发

- 支持文字输入现有食材。
- 按食材组合生成 3 到 5 道外卖菜品。
- 支持历史菜品查询和当前会话菜品查询。
- 使用 LangGraph 编排意图分类、识图、模型调用、工具循环和结果解析。

### 上架素材

- 生成菜名、卖点、食材、步骤、成本估算、建议售价、标签和上架描述。
- 支持 Tavily 参考图搜索。
- 支持 DashScope `qwen-image-2.1-turbo` 生成菜品图。
- Pydantic 校验模型返回的结构化菜品数据。

### 工程能力

- Chainlit 聊天界面。
- SQLite 菜品和会话记录。
- LangGraph `MemorySaver` 多轮状态。
- 上下文限制：12 条消息、12000 字符、单次工具结果 8000 字符。
- 工具调用、checkpoint、意图路由和结构化输出测试。

## 数据与持久化

- `dish_development.db` 仅保存在本地，不提交到 GitHub。
- 已持久化会话编号、菜品、食材、步骤、文案、成本文本和图片 URL。
- 当前不持久化完整聊天内容。
- `MemorySaver` 只保存当前 Python 进程内的对话，重启后丢失。
- 新聊天会生成新的 `session_id`，当前界面不能浏览其他会话的历史菜品。

## 已知问题

- 成本和售价仍是文本，不能直接计算毛利。
- 没有商家画像、菜单目录、审批状态和 CSV 导出。
- 没有用户认证、租户隔离和权限控制。
- 没有历史会话列表和完整聊天恢复。
- 没有评测集、tracing 和线上监控。
- 生成图与实际菜品的一致性尚未做合规校验。
- MCP、multi-agent 和会话摘要尚未实现。
