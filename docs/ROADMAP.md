# 路线图

> 最后更新：2026-10-25

## 产品目标

把 recipe-agent 做成面向外卖中小商家的菜单研发与上架 Agent，而不是通用菜谱生成器。

完整闭环：

```text
食材输入
  -> 菜品研发
  -> 成本与毛利
  -> 上架素材
  -> 人工确认
  -> 菜单导出或平台发布
```

## 功能分区

### 1. 食材理解

- 图片识别食材。
- 食材清单可编辑。
- 多图输入。
- 保留当前会话的食材库存。

### 2. 菜单研发

- 单道和多道菜品研发。
- 根据品类、客单价、后厨能力和目标人群调整方案。
- 历史菜品查询与复用。

### 3. 经营经济

- 食材用量和采购单价。
- 单份成本、包装成本、平台成本和毛利。
- 建议售价与价格带。
- 成本误差和 POS 数据核对。

### 4. 上架素材

- 菜名、卖点、详情和标签。
- 实拍菜品图优化。
- AI 菜品示意图生成。
- 图片与真实菜品一致性提示。

### 5. 审核发布

- 商家改价和编辑。
- 人工确认和审批状态。
- CSV 和素材包导出。
- 外卖平台或小程序发布适配。

### 6. 知识评测

- 平台规则、过敏原和经营规则知识库。
- RAG 检索和引用。
- 测试集、tracing、token 和失败原因统计。

## 下一阶段

### P0：经营数据基础

1. 把成本和售价改成结构化数值字段。
2. 用 Python 计算成本、毛利和价格带，不让模型口算。
3. 建立商家画像和菜单目录。
4. 建立历史菜品中心，支持查看历史会话和菜品。
5. 增加人工改价、确认和 CSV 导出。

验收标准：

- 能输入采购单价和用量。
- 能稳定计算单份成本和毛利。
- 能浏览历史菜品。
- CSV 字段完整且可再次导入。

### P1：图片与规则

1. 增加真实菜品图优化接口，区分“实拍优化”和“AI 示意图”。
2. 增加平台文案、过敏原和夸大宣传检查。
3. 建立 20 组食材输入和 5 个商家画像。
4. 接入 RAG、引用和评测。

验收标准：

- 生成图不会被标成真实菜品照片。
- 规则命中可解释。
- 评测结果可重复运行。

### P2：POS、MCP 与试点

1. 导入 POS 或菜单 CSV。
2. 用 MCP 接入外部库存、菜单或经营系统。
3. 持久化 LangGraph checkpoint。
4. 找 2 到 3 个真实商家或同学模拟试点。
5. 部署并补充认证、限流和监控。

验收标准：

- 菜单经营数据可追踪。
- 旧会话可以恢复。
- 试点指标来自真实测量。

## 暂不做

- 不承诺外卖平台一定提供开放发布 API。
- 不把 AI 生成图说成真实菜品照片。
- 不在没有认证和租户隔离的情况下直接服务多商家。
- 不为增加技术数量而同时引入 multi-agent、MCP 和复杂 RAG。
